# MimiVent App 结构优化与重构方案

审查日期：2026-10-25。状态：第一至第五阶段已完成。各阶段实施与验收记录见文末“实施记录”。

## 1. 目标与执行原则

将已经通过用户真机验证的 App 整理为便于维护、复用和扩展的工程，同时保留当前功能与视觉交互。范围包含文件组织、页面管理、状态管理、组件、工具函数、主题、弹窗、规范、自适应与平台边界。

无法仅靠结构设计保证绝对没有新问题。实施时用行为基线、分阶段迁移、自动化回归和真机验收控制风险；每阶段可独立回退，不同时改通信协议、交互语义、依赖版本和视觉效果。

- 沿用 `custom_3.22.0_harmony`、Dart 3.4、JDK 11 及现有依赖版本。技能示例涉及的新版本 API 不能直接搬入项目。
- 推荐轻量 MVVM：View + ViewModel + DeviceRepository + 传输适配层，继续使用 ChangeNotifier。
- 依赖通过构造函数注入；每次 App 会话只创建一套设备连接、请求队列与状态仓库。
- 状态向下传递、用户操作向上提交。设备报告的运行状态是运行事实来源，App 不重新实现固件的 PIR / 排风状态机。
- 本次不需要通用用例层、全局服务定位器或全面更换状态管理框架。
- 可替换通信边界为后续 Wi-Fi 留入口；当前只实现 BLE，不生成空的 Wi-Fi、云服务或其他平台实现。

## 5. 状态与依赖管理

### 5.1 状态归属

| 状态 | 唯一持有者 | 规则 |
| --- | --- | --- |
| 硬件连接、扫描、GATT 资源 | BLE 适配层 | 只有适配层操作插件；输出只读连接/扫描事件。 |
| 已确认的设备快照、会话标识 | DeviceRepository | 接收 API 结果后原子发布；页面不能直接赋值。 |
| App 选中环境与偏好 | 仓库 + PreferencesStore | 与固件 activeProfile 分开，明确不一致时的行为。 |
| 待保存的配置草稿 | SettingsViewModel | 按 session + profile 绑定；普通状态轮询不覆盖草稿。 |
| 操作进行中、操作结果、确认意图 | 对应 ViewModel | 使用明确的操作阶段；多个控制入口共享设备写操作锁。 |
| 当前 Tab、滚动、弹窗展示、动画进度 | 页面 / UI Coordinator | 不持久化，不进入固件业务状态。 |

三个功能 ViewModel 共享同一个 DeviceRepository，设备快照使用不可变对象并只读暴露；ViewModel 不分别维护可变的设备副本。

Repository 内封装轮询和写操作协调，正在写操作时避免状态读取干扰；已经开始的读取返回时仍需校验是否过期。事务内的 BLE 报文仍串行发送，这是通信约束，不等于把用户操作按排风时长排队。

### 5.2 类型与返回值

- DeviceMode、DevicePhase、DeviceAction、TimingField 使用明确类型，wire 字符串在接口边界统一映射。
- 未知固件枚举值保留原始值并显示兼容提示；不要误当成可执行的自动模式。
- TimingSettings 按五个字段实现值比较和 hashCode，取代 Map.toString 比较。
- 命令返回执行、阻止、取消、失败等明确结果。只有设备确认成功才显示“已启动/已保存”。
- 区分连接中、GATT 可用、初次同步中、可操作；只有初次状态和配置同步完成后才允许操作。
- 保留原始失败信息用于日志，界面显示稳定的可读信息；取消操作不显示为设备故障。

### 5.3 会话与并发

- 扫描、连接、断开、切换环境分别有有效性标识。旧扫描完成不能覆盖新连接，旧请求不能覆盖新会话。
- 请求入队时捕获会话；断开时拒绝待发旧请求、结束正在等待的响应并清空解析器。不能在重连后执行上次会话遗留命令。
- prepare / confirm 持续关闭作为一个受锁保护的操作，UI 只出现一次用户确认；不把固件两阶段协议表现成两次用户确认。
- 关闭和 dispose 顺序明确：停止新请求、失效旧任务、取消轮询/订阅、清理连接，再结束通知。异步任务不能在 disposed 后 notify。
- 构造注入 Transport、PreferencesStore 和必要的时钟/计时接口，便于用可控异步结果测试顺序。
- 控制写入失败不盲目重试：重复发送可能改变设备实际行为，应先重新读取并由用户决定后续操作。

## 6. 页面与导航管理

- AppShell 只负责导航、顶栏、背景和生命周期衔接；连接页、控制页、设置页独立。
- 现有两个 Tab 继续使用 IndexedStack，保留各自滚动位置；顶部只响应当前活动页面的纵向滚动。
- 顶栏滚动值属于 UI，不能因横向滑动、后台页面滚动或设备每秒轮询被重置。
- 当前阶段不必引入路由库；后续增加设备详情、记录详情、设置子页或深链接时，再在 AppShell 之外引入命名导航 / Router。
- 切换布局和窗口大小时保持 ViewModel、当前 Tab、设置草稿和会话，不因断点变化重新扫描或重建 Repository。
- 状态监听尽量定位到相关卡片；主题背景、固定说明与底部导航避免随着每秒状态刷新整棵重建。是否需要更多优化以性能测量为依据。

## 7. 主题、背景、字体与动画规范

- 先逐项迁移现有视觉数值，保留目前用户认可的深色渐变、金色运行光效和风扇动画。
- ThemeData 管理 ColorScheme、TextTheme、按钮、输入、菜单、对话框和底部面板主题。
- MimiVent ThemeExtension 管理背景渐变、卡片渐变、展示/运行阴影、表面层级、状态色、圆角和必要间距。
- 颜色使用语义名，如 fanRunning、activityDetected、danger、onAccent、mutedText，避免页面自行挑颜色。
- 文本采用明确层级：品牌标题、卡片主状态、正文、辅助说明、紧凑标签。保留中文系统回退字体；新字体需确认字库覆盖、授权和包体影响。
- 暗色外观提取完成后可扩展浅色/跟随系统；本次先不自动加入主题切换入口。
- AppBackground、DisplayCard、OperationCard 分工明确，展示卡和按钮保持用户已确认的视觉区别。
- 状态标签单行、紧凑；字号放大时允许横向滚动或调整卡片布局，不强行裁切文字或禁用全局字体缩放。
- 风扇放大、旋转和减速共用动画进度；提取后保持当前参数：启动 1,800ms、停机 1,600ms、稳定缩放 1.5 倍。数值来自本轮源码，不顺带改变视觉效果。
- Logo 呼吸、搜索波纹、弹窗关闭与控制页变清晰分别独立封装；没有运行的动画不持续消耗帧。
- 提供减少动态效果的适配策略，并验证停机最终转速为零、图标回到待机尺寸。
- 原生 Android 启动背景与 Flutter 深色背景统一，避免启动时白色闪屏；作为单独视觉任务验收。

## 8. 弹窗与交互管理

ModalCoordinator 是 UI 范围内的协调器，通过页面 context / Navigator 展示，不向 Repository 注入 BuildContext，也不建立永久保存已销毁 context 的全局单例。

- 统一确认、危险确认、时间选择、连接面板和错误反馈的入口与样式。
- 同一种弹窗 single-flight；已打开时复用当前 Future 或忽略重复打开，不堆栈、不排队弹出多份确认。
- 扫描轮次与弹窗显示分离：关闭扫描弹窗只隐藏本轮 UI，不因后续扫描结果再次自动弹出。主动点击仍可打开。
- 确认对话框返回确认/取消。确认后复核会话、设备、环境、操作条件，不能拿过期弹窗的确认直接操作新会话。
- 如果确认期间任务发生实质变化，拒绝旧确认并显示最新状态，不静默替换成更危险的操作。
- 相同临时操作再次点击，从当前时刻重新计满配置时长；不弹重复任务的覆盖确认、不等待旧倒计时结束。
- 切换不同操作时按现有规则确认一次；持续关闭再次点击时确认恢复自动感应。
- 执行中统一禁用冲突入口；busy / 取消 / 未执行不能显示成功 toast。
- 明确遮罩点击、返回键、拖动关闭和关闭按钮的一致策略；连接中如禁止关闭，所有关闭路径都一致受控。若后续增加取消连接，则显式取消连接任务并清理会话。
- 连接成功且初次同步完成后，先关闭连接面板，再完成控制页清晰动画；切后台/失败/销毁也应清理模糊状态。
- Toast 适合短反馈，阻断错误用可恢复卡片/对话框；轮询错误避免每秒重复弹 toast。
- 时间选择器在独立 StatefulWidget 中管理并释放滚动控制器，接收当前值、候选值、允许 0 与取消/确认结果。

## 9. 自适应：横屏、平板、折叠屏和桌面

### 9.1 以窗口约束决定布局

以下断点为方案起点，单位为 Flutter 逻辑像素；实施时按内容能否合理容纳校准，不能按手机/平板型号或屏幕方向硬编码。

| 可用宽度 | 页面布局 | 导航与弹窗 |
| --- | --- | --- |
| < 600 | 当前单列为主，信息卡按宽度决定单列/双列 | 保留底部导航；高度足够时底部面板，小高度时有界对话框或全屏选择页。 |
| 600–1,023 | 宽度足够时状态/操作与配置并列；控制正文限制最大宽度 | 可用侧边导航；设备连接/时间选择以居中有界窗口呈现。 |
| >= 1,024 | 侧边导航 + 有最大宽度的内容区，信息与操作分区 | 桌面式居中弹窗，明确焦点、键盘和滚动交互。 |

- LayoutBuilder 按局部约束布局，MediaQuery 获取安全区域、文字缩放和显示特征；窗口变小会自动回到紧凑布局。
- 另检查可用高度：手机横屏即使很宽，高度仍可能很小，不强制套用平板的高卡片和大弹窗。
- 页面主体保持可滚动；设备列表数量增加时只滚动受限列表区域。按钮、标签与设置行避免依赖固定高度容纳任意字号。
- 宽屏适当增加列数与留白，保留内容最大宽度，避免卡片横向拉满整块桌面。
- 每个 Tab 的纵向滚动位置与顶栏状态独立保持；响应式重排不丢用户正在编辑的草稿。

### 9.2 折叠屏和运行中改尺寸

- 使用窗口实际尺寸，不假设折叠屏总是“大屏”。展开、折叠、分屏与旋转仅改变布局。
- 检查显示特征信息，避免操作按钮或弹窗跨越不可用铰链区域；需要双窗格时按连续可用区域分配内容。
- 折叠/旋转不等同于业务退出，不主动断 BLE；生命周期事件仍按实际前后台策略处理。
- 处理 SafeArea、刘海、系统手势区、桌面标题栏与窗口内边距。

### 9.3 桌面及平台能力

- 增加可见焦点、Tab 遍历、Enter/Space 操作、Escape 关闭允许取消的弹窗；避免按键重复触发设备写操作。

## 10. 代码与工程规范

- 文件 snake_case，类 PascalCase，方法与字段 lowerCamelCase；内部实现用私有成员。
- 公开状态通过只读 getter / 不可变对象暴露，变更只通过明确方法；不允许页面直接写 Repository 字段。
- 默认中文注释：模块说明职责与边界，关键方法说明前置条件、失败路径和异步失效规则；避免逐行复述代码。
- dart format 统一格式；flutter_lints 为基础，结合现有 Dart 3.4 支持范围逐步启用异步、订阅清理和不可变对象规则。
- Future 必须 await 或明确 unawaited 并处理错误；仅在可解释的清理场景吞异常，必要时保留调试日志。
- Subscription、Timer、Ticker、AnimationController、ScrollController 都有明确创建者与释放者。
- 调试日志带模块、动作、sessionEpoch 和结果；不记录凭证，不在生产环境持续输出每秒完整状态。
- 尽量使用 package:mimivent_app/... 或一致的相对导入规范；选定一种并由 lint 约束，迁移时统一。
- 一类改动对应一个可审阅阶段：纯移动、主题提取、状态调整、异步修复分别进行。
- 保持 applicationId、协议 UUID、环境存储键和固件字段兼容；变更需单独设计迁移。
- 依赖版本升级、发布签名与跨平台接入单独排期。当前 release 使用 debug key，正式分发前应建立签名与备份流程，本轮不生成密钥或改签名。
- 文档注明当前 App 版本与固件版本分别从何处读取，并保持界面、文档、实际安装包版本一致。
